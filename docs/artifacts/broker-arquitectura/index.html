omp-session-broker

protocolo 1.0.0 bun run verify · exit 0 Bun + TypeScript + SQLite

Broker de sesiones standalone: coordina sesiones OMP entre sí con autenticación por grants, dedup durable y recovery honesto — sin ejecutar inferencia ni sustituir la TUI nativa.

01

Arquitectura general

Cinco paquetes con fronteras congeladas. El broker es un proceso único con SQLite; los clientes se conectan outbound por WebSocket; el adaptador vive dentro de cada sesión OMP y conserva su TUI.

02

Flujo ask / reply correlacionado

Solo una herramienta explícita session_reply(replyTo=requestId) completa un ask. Ni agent_end ni el siguiente texto del modelo cuentan como respuesta.

03

Máquina de estados del request

Estados congelados en REQUEST_STATES. Los terminales nunca re-entregan; outcome_unknown solo se resuelve reconciliando.

04

Seguridad en tres capas

05

Backup y restore conservador

El backup restaura datos, no confianza: lo ocurrido después del snapshot no se asume.

Backpressure, gates y verificación

event queue / subscription1000 ítems / 4 MiB → corte explícito
retention request/event7 d → CURSOR_EXPIRED (exit 15)
cursorTtl1 h → snapshot con gap: true

Gates (cerrados por defecto)

G-BROKER-LIVE

Inferencia/proveedores reales y gasto. Opt-in del operador; fuera del DoD. Todas las suites usan fake model que falla si se invoca.

G-BROKER-SERVICE

Servicio systemd user persistente. Solo artefactos de ejemplo en ops/systemd/; nada instalado ni arrancado.
